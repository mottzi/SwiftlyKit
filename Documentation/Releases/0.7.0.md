# Triple 0.7.0

Prepared release notes. The `0.7.0` tag has not been published.

Triple is the new name of SwiftlyKit. This is the first version planned to export
the `Triple` Swift package product and module. Existing `0.6.0` and earlier tags
continue to export `SwiftlyKit`.

To migrate, change the package URL to `https://github.com/mottzi/Triple.git`,
the library product and imports to `Triple`, the facade to `Triple`, and the event
and error types to `TripleEvent` and `TripleError`. Existing cache and coordination
directories remain compatible with previously installed clients. Swiftly remains
the external toolchain manager.

Package configuration now evaluates only the root manifest through
`configurePackage(using:)`. It can return executable products without resolving
dependencies. Builds still validate the full dependency graph before compiling.
Use the returned `configuration.environment` to preserve host SDK recovery.
Host manifest caches include the compiler and SDK identity, so replacing either
cannot reuse results from the old installation.

Host SDK recovery also works when a cold dependency fetch produces a long log.
Triple classifies recognized compiler failures from the captured command output,
then retains a bounded diagnostic for callers. A compiler failure buried between
the diagnostic's retained prefix and suffix still triggers an installed SDK
retry. Ordinary manifest and dependency errors continue to stop inspection.

Builds now use the selected toolchain's default SwiftPM build system. Triple
verifies resources through native link metadata on Swift 6.3 and the selected
product's Swift Build project model on Swift 6.4. Export includes resources from
the executable and its linked dependencies. Verified privacy-only resource
bundles are omitted from results and exports, including Swift Build bundles with
a generated `Info.plist`.

Requires an Apple silicon Mac, macOS 13 or later, and Xcode or Command Line Tools
with Swift 6.3 or later. The calling app or command-line tool must be unsandboxed.

## Verification

Resource runtime verification covers library source revision
`513be38e4dcb137c7cd19cb76a101d387fd12c4c`. The preceding library suite passed
352 tests in 46 suites on Swift 6.4 with every
opt-in case enabled. This includes real subprocess cancellation, host manifest
cache recovery, traits, consecutive-build identity, and eight cross-compilation
build/export combinations. The preceding recorded checks also passed 352 tests
on Swift 6.3.3.

Stripped Swift 6.3.3 and 6.4.0 release exports loaded both executable and dependency
resources after the original scratch directories were removed. x86_64 execution
ran natively on Ubuntu Linux; ARM64 execution ran through QEMU user-mode emulation
on the same Linux host. Commands and output are recorded in
[`Linux-resource-execution.md`](../Research/Triple/Linux-resource-execution.md).

The cold-cache SDK recovery fix adds regressions for long compiler output during
inspection and resolution, bounded exhaustion diagnostics, and ordinary errors
that must not trigger retries. The updated full suite passed 354 tests in 46
suites with every opt-in case enabled. It also passed a real Deployer inspection with an
empty, isolated dependency cache, keeping Swift 6.3.3 while recovering from SDK
27.0 to SDK 26.5. Evidence is recorded in
[`Cold-cache-host-SDK-recovery.md`](../Research/Triple/Cold-cache-host-SDK-recovery.md).
